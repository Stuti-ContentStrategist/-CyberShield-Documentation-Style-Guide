# 🔤 Writing Conventions

## 🧱 Overview

The **Writing Conventions** section ensures consistency across all CyberShield documentation.\
It defines how to use capitalization, punctuation, tenses, numbers, terminology, and naming conventions so that every document reflects the same professional standard.

> 💡 **Tip:** Consistency builds reader trust — even small grammatical or stylistic differences can make a product feel less polished.

***

#### ✍️ General Grammar Rules

| Rule                              | Example                                   | Avoid                                                                        |
| --------------------------------- | ----------------------------------------- | ---------------------------------------------------------------------------- |
| Use **active voice**              | ✅ “Restart the service to apply changes.” | 🚫 “The service should be restarted.”                                        |
| Keep sentences short and direct   | ✅ “Click **Save** to confirm.”            | 🚫 “The user will need to click the Save button to confirm.”                 |
| Use **present tense** for actions | ✅ “CyberShield encrypts all data.”        | 🚫 “CyberShield will encrypt all data.”                                      |
| Use **consistent terminology**    | ✅ “Security Dashboard” everywhere         | 🚫 “Dashboard,” “Control Panel,” and “Security Console” used interchangeably |
| Avoid filler words                | ✅ “Open the configuration file.”          | 🚫 “You just need to open the configuration file.”                           |

***

#### 🔡 Capitalization

| Element                 | Rule                                                                     | Example                                                                             |
| ----------------------- | ------------------------------------------------------------------------ | ----------------------------------------------------------------------------------- |
| **Headings**            | Use **sentence case** (capitalize only the first word and proper nouns). | “Installing CyberShield” ✅ not “Installing cyberShield” or “INSTALLING CYBERSHIELD” |
| **Buttons & UI Labels** | Match what appears on the screen.                                        | “Click **Save Settings**.”                                                          |
| **Product Names**       | Always capitalize “CyberShield Security Suite.”                          | ✅ CyberShield Security Suite                                                        |
| **Features & Modules**  | Use title case for feature names, lowercase for general terms.           | “Threat Analytics,” “multi-factor authentication”                                   |
| **Acronyms**            | Write in uppercase on first use, with expansion if needed.               | “CyberShield uses MFA (Multi-Factor Authentication).”                               |

> 🧠 **Info:** Avoid ALL CAPS for emphasis — use bold or callouts instead.

***

#### 🔢 Numbers & Measurements

| Rule                                                                   | Example                                               |
| ---------------------------------------------------------------------- | ----------------------------------------------------- |
| Spell out numbers **one through nine**; use numerals for 10 and above. | “Scan every five minutes,” “Run 15 concurrent tasks.” |
| Always include units with numeric values.                              | “The timeout period is 30 seconds.”                   |
| Use consistent formatting for time and dates.                          | “November 9, 2025” not “9th Nov 2025.”                |
| Use commas in large numbers.                                           | “2,000 users,” not “2000 users.”                      |

***

#### 🧩 Terminology

To maintain consistency across all product documents, use the following standard terms:

| Preferred Term        | Avoid Using                   | Notes                                                      |
| --------------------- | ----------------------------- | ---------------------------------------------------------- |
| **CyberShield Agent** | Client app, endpoint software | Use “Agent” for installed components.                      |
| **Dashboard**         | Admin Console, Control Panel  | Always “Dashboard.”                                        |
| **Scan**              | Check, Sweep                  | Use “Scan” when referring to threat analysis.              |
| **Alert**             | Notification                  | Use “Alert” for security events only.                      |
| **Policy**            | Rule, Configuration           | Use “Policy” when referencing user-defined security rules. |

> ⚙️ **Note:** Use product-specific capitalization and spellings consistently across all guides.

***

#### 🧾 Lists and Bullets

| Type                         | Use Case                                      | Example                                                      |
| ---------------------------- | --------------------------------------------- | ------------------------------------------------------------ |
| **Numbered lists (1, 2, 3)** | Sequential steps or procedures                | “1. Open the Dashboard → 2. Select Policies → 3. Click Add.” |
| **Bulleted lists (•)**       | Non-sequential items                          | “The Dashboard displays: • Alerts • Scans • Reports.”        |
| **Nested lists**             | Use only when necessary; keep two levels max. | Helps readability.                                           |

> 💡 **Tip:** Avoid long multi-level lists — if your steps exceed two levels, turn them into sub-sections.

***

#### ✍️ Punctuation & Symbols

* Use **en dashes (–)** for ranges → “10–15 seconds”
* Use **em dashes (—)** for emphasis → “CyberShield — built for security — runs quietly in the background.”
* Use **Oxford commas** → “Policies, alerts, and logs.”
* Avoid exclamation marks (!) in technical writing.
* Use quotation marks for UI text, not italics.

> 🧠 **Info:** Punctuation should clarify, not decorate — prioritize readability.

These writing conventions ensure that all CyberShield content remains accurate, readable, and stylistically consistent across every guide.
